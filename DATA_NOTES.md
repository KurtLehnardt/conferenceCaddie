# Data notes

Talk data now comes from any Linux Foundation event whose schedule page embeds Sessionize. `scripts/ingest.mjs` discovers events, fetches each source once per run, writes the raw responses under `data/raw/{slug}/`, and builds `data/{slug}/talks.ndjson` and `data/{slug}/conference.json`. `node scripts/ingest.mjs --no-fetch --event <slug> --dry-run` rebuilds both files from the committed raw files with no network call; the output is byte-identical to the fetching run. The MVP's `scripts/build-data.mjs`, `data/raw/schedule.json` and `data/talks.ndjson` are gone.

Raw data was fetched on 2026-11-09 with the User-Agent `ConferenceCaddie-ingest/0.2 (+https://github.com/KurtLehnardt/conferenceCaddie)`, one request per URL and a one-second pause between requests.

## Sources and how they chain

1. The LF list, `https://events.linuxfoundation.org/wp-json/lfevents/v1/events?status=upcoming`, saved as `data/raw/lf-events-upcoming.json`. It held 62 events. It has no slug, so the slug is `slugify(name)` plus `-{year}` when the name does not already end with the year. All 62 slugs are unique; a collision would abort the run.
2. The event's `cta_schedule_url` page, saved as `schedule-page.html`. Its `data-sched-config` attribute, HTML-decoded and parsed, is saved as `sched-config.json`. The Sessionize api code and public slug are read only from this config and are never derived.
3. `https://sessionize.com/api/v2/{apiCode}/view/All`, saved as `view-all.json`. Sessions reference rooms, speakers and category items by id, and the same response carries the name tables.
4. `https://{publicSlug}.sessionize.com/api/data`, saved as `api-data.json`. Its `timezone` is a Windows zone name.

## Time zones

`data/windows-zones.json` maps 142 Windows zone names to IANA zones. It is generated by `node scripts/build-windows-zones.mjs` from the territory `001` rows of CLDR `windowsZones.xml` and committed. It necessarily contains entries such as `"Mountain Standard Time": "America/Denver"`; that is reference data, not a hard-coded conference.

A Windows name missing from the table makes the event unavailable with `time_zone_unmapped`, prints the name, and indexes nothing. A missing `timezone` makes it unavailable with `time_zone_missing`, unless `data/conference-overrides.json` names an IANA zone for the slug. The CLI prints the exact override entry it would need and never writes it.

PyTorch Day Japan's Sessionize site is not published. Its `api/data` returns a different payload (`"IsSchedulePublished": false`, `"Timezone": null`), so Sessionize gives no time zone. `data/conference-overrides.json` therefore holds `{"pytorch-day-japan-2026": {"time_zone": "Asia/Tokyo"}}`. This is an operator decision based on the LF list placing the event in Tokyo, Japan, which has a single time zone; remove the entry to make the event unavailable instead.

Offsets are computed per instant with `Intl.DateTimeFormat(..., { timeZoneName: 'longOffset' })` in the event's zone. KubeCon is `-07:00` throughout, MCP Dev Summit Nairobi `+03:00` and PyTorch Day Japan `+09:00`.

## Session URLs and the unpublished-site fallback

When `api/data` carries a lowercase `timezone` string the public site is live, and each talk's `url` is `https://{publicSlug}.sessionize.com/session/{id}`. Otherwise the per-session page is a Sessionize placeholder ("Your event mobile app can be here!"), so every talk's `url` falls back to the conference's `official_schedule_url`, the LF schedule page. For PyTorch Day Japan all 19 urls are `https://events.linuxfoundation.org/pytorch-day-japan/program/schedule/`.

## Group mapping

Groups are assigned from the config and the feed only; no conference name or id appears in the code.

- Track: the group whose title equals `primaryFilterTitle` (trimmed, case-insensitive), else the lowest-sort group that is not hidden. `track` is the session's first item in it, else "Not specified".
- Level: the first remaining group whose title contains "level". Without one, `level` is null and the conference has no level filter.
- Hidden: groups named in `hiddenFilterCategories`, matched case-insensitively because the config spells "Subtopic" where the feed has "SubTopic". They produce no tags but are still read for sponsor detection.
- Tags: every other group, as `{group, value}` pairs in group order then item order, plus `tag_keys` joined with U+001F.

| Conference | Track group | Level group | Tag groups | Hidden groups | Slides question |
|---|---|---|---|---|---|
| KubeCon + CloudNativeCon North America | All Sessions | Audience Level | End User Programming, Solutions Showcase Programming | SubTopic, CNCF Projects, Is Sponsored Keynote | Presentation Slides |
| MCP Dev Summit Nairobi | Topic | Audience Level | none | none present in the feed | Presentation Slides |
| PyTorch Day Japan | Topic | none | none | none present in the feed | none |

`presentationSlidesQuestionId` holds a question title, not an id, so it is matched against question titles. PyTorch Day Japan's only question is "Presentation File (PDF)", so no talk there has slides.

An organiser renaming a group between runs changes that conference's chips on the next run. That is intended.

## Kind rules

First match wins.

1. housekeeping: no description, and the title is an opening, a closing, a welcome, "remarks", a wrap-up or "welcome back".
2. break: no speakers, and either the title before any " | " mentions coffee, lunch, breakfast, registration, badge, coat, bag check, snacks or a reception, or the track name contains "break", "breaks" or "registration". The track rule covers "Breaks + Meals + Special Events" in the two small feeds.
3. talk: at least one speaker.
4. ambient: no speakers and nothing above matched.

## Sponsor rule and the sponsored-keynote change

`sponsor` is true when any category item of the session, hidden groups included, has "sponsor" in its item name or group title; when the track name contains "sponsor"; or when the title says "sponsored by", "sponsored keynote" or "in-booth demos". Descriptions are not used, because many carry boilerplate about sponsored content.

On KubeCon this flags 72 sessions, 49 of them talks. The MVP flagged 62 (39 talks). The difference is the 10 keynotes that now carry the organiser's "Is Sponsored Keynote: Sponsored" item, which the MVP's track-and-title rule could not see. "Hide sponsor content" now hides those keynotes too.

## Speaker profiles

Each talk document carries `speaker_profiles`, `[{ name, tagline, links: [{ title, url }] }]`, in the session's speaker order, from the view/All speaker table. `tagline` is null when the feed has none. Only links whose url starts with `http://` or `https://` (any case) are kept. On KubeCon 763 of 866 talk speaker slots have at least one link; on MCP 48 of 58; on PyTorch Day Japan none, because its speakers have no links yet.

## Re-runs and embeddings

Every document carries `text_hash` (sha256 of title, a newline and abstract) and `content_hash` (sha256 of the canonical JSON of every other built field). Before indexing an event the CLI reads the stored hashes for that conference. Unchanged documents are skipped; documents whose text is unchanged but other fields changed get a Bulk API partial `update` without `title` and `abstract`, which keeps the stored embeddings; changed text is re-indexed; ids that left the feed are deleted. Deletions are limited to the event being processed. `topics` is set by the topics step, not by the importer, so it is outside both hashes and survives skips and partial updates.

Verified on 2026-11-09 against throwaway indices that were deleted afterwards: MCP and PyTorch indexed into a lexical index (79 documents), a second run reported `0 new, 0 updated, N unchanged, 0 deleted`, and moving one MCP session to another room produced exactly one `update` and no `index`. On a semantic_text index holding only PyTorch Day Japan (19 documents), the same room change went through as one partial update, the document kept its title and its title and abstract embedding chunks, and a semantic query still ranked it first.

## Co-located events

As found by the phase-2 design fetch on 2026-11-09, the 11 KubeCon co-located LF entries point their `cta_schedule_url` at their own pages under `/co-located-events/`, and those pages carry no `data-sched-config`. The co-located schedule lives on a separate page with its own Sessionize feed, which is not an entry in the LF list. Because an api code is never guessed, those events end as unavailable with `no_sched_config` and link to their official pages. The apiCode de-duplication (`shares_feed`, `parent_slug`) stays in place for the day an LF page does carry a shared config.

## Unavailable examples committed

- `yocto-project-virtual-summit-2026-12-2026`: no `cta_schedule_url`, so `no_schedule_url` and no page fetch. Only `lf-event.json` is in its raw directory.
- `open-source-summit-japan-2026`: its schedule page embeds Sched (`ossjapan2026.sched.com`), not Sessionize, so `no_sched_config`.

## Odd things

- KubeCon's "Save Phippy: The Cloud Native Escape Room Hosted by Teleport" runs 19:00 to midnight, so its `end` is on the next day and `end_minutes` is 1440.
- Talks with speakers but no description keep an empty `abstract`: four on KubeCon ("From Pod to Actuator: Physical AI and the Future of Kubernetes", "CNCF Bingo: Play, Learn, Win!!!!!!", "Human Scale, Agent Scale", "A Tribute to Open Source") and two on MCP ("Keynote: From Answers to Action: What Safety Means in the Age of AI Agents", "Panel: Alternative Agentic AI Inferencing: Edge-swarm Orchestration in Low Resource Settings").
- MCP's "Keynote: To be Announced" and "Keynote: Agentic E2E Software Factories with MCP - Speaker to Be Announced" have no speaker yet, so they are ambient and not searchable until the organiser adds one. PyTorch Day Japan has one such keynote.
- MCP's "Keynote: Welcome Back" is housekeeping through the "welcome back" rule.
- MCP's "Women and Non-Binary Community Gathering" has no speakers and sits in "Breaks + Meals + Special Events", so the track rule makes it a break.
- Some KubeCon track names carry an emoji prefix exactly as the feed spells them, for example "📚 Tutorials" and "⚡ Lightning Talks".
- 40 KubeCon talks have a speaker without a tagline, so `speaker_taglines` is not aligned with `speakers` by position. `speaker_profiles` is aligned and uses null.
- `isServiceSession` is false on every session of all three feeds and is not used. Every session has a room.
